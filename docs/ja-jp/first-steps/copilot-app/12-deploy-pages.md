Space Quiz を GitHub Pages にデプロイして、誰でもアクセスできるようにします。Copilot はワークフローを準備し、デプロイを案内できますが、変更をレビューし、サイトが公開されたことを確認するのはユーザーの責任です。

このレッスンでは、次の操作を行います。

- Copilot に GitHub Pages のデプロイ設定を依頼します。
- マージする前にワークフローとプルリクエストをレビューします。
- デプロイの進行状況を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz は GitHub リポジトリにありますが、まだ誰でも簡単に使える状態ではありません。GitHub Pages を使って単一ファイルのサイトを公開すれば、サーバーやランタイム依存関係を追加せずに公開 URL からアクセスできます。

## Copilot にサイトのデプロイを依頼する

`space-quiz` の Copilot アプリのセッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を有効にしてください。必要であれば、Web サイトをビルドして GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの概要とローカルでの実行方法を説明する README を追加してください。変更内容でプルリクエストを作成し、必須チェックに合格したらマージしてください。デプロイが成功するまで監視し、実際の Web サイトの最終 URL を教えてください。Pages の有効化やマージの権限がない場合は、何を承認するか、何を行う必要があるかを正確に説明してください。サイトが実際に公開されるまで、成功したと報告しないでください。
```

> [!WARNING]
> このプロンプトは、エージェントにプルリクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。続行する前に、diff、デプロイ権限、GitHub の承認リクエストを確認してください。

## ワークフローをレビューしてデプロイを確認する

1. リポジトリに README がない場合に限り、README が追加されていることを確認します。
2. ワークフローのビルド手順とデプロイ手順を含め、プルリクエストの変更をレビューします。
3. 必須のプルリクエストチェックに合格した後にのみマージします。
4. GitHub Actions のデプロイ実行が成功するまで確認します。
5. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages を有効にできない場合やプルリクエストをマージできない場合は、提示された具体的な手順に従います。デプロイが成功し、実際のサイトが読み込まれるまで、作業を完了と見なさないでください。
